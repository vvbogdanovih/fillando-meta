# Відновлення каталогу в новій базі

Оновлено 2026-09-11: одноразовий перехід каталогу завершено. `scripts/fillando_v_2/`
і команди `yarn migrate*` видалено з поточного backend.

## Актуальний дамп

Для нового середовища відновлювати актуальну повну копію бази за
[ранбуком локальної MongoDB](local-mongodb.md). Разом із товарами мають бути перенесені
категорії, кольори, лендінги та решта пов’язаних колекцій. Спершу перевірити namespace дампу
і використовувати нову порожню базу; старі seed-скрипти більше не потрібні.

Після restore перевірити схему даних, запустити сумісні бекенд і фронтенд, очистити кеші
й перевірити фільтри, товари та фід. Окремі міграції виконувати лише за потребою конкретного
релізу — [список збережених інструментів](../../repos/fillando-be/scripts/README.md).
Міграція `is_required` має власні [команди перевірки й відкату](../../repos/fillando-be/scripts/migrations/category-attribute-requiredness.md).

## Дамп до переходу каталогу

Для дуже старої копії потрібні старий код і тодішній порядок міграцій. Вони збережені в
Git **бекенду**, коміт `c091e43dcabab0e287f0079545e3ab133a6da5f2`:

```sh
git show c091e43dcabab0e287f0079545e3ab133a6da5f2:scripts/fillando_v_2/README.md
git show c091e43dcabab0e287f0079545e3ab133a6da5f2:src/docs/CATALOG_RELEASE.md
```

Відновлення такого дампу проводити окремо від production, у відокремленій копії історичного
коду. Старий ланцюжок не враховує нові контракти й не призначений для повторного запуску на
чинному каталозі. Зберегти оригінальний дамп і звіти перед будь-якими перетвореннями.
