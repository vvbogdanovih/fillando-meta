# PDF-документи

- [Поточний план і прогрес](fillando-implementation-plan.pdf) — генерується з
  [Plan-0010](../plans/plan-0010-general-catalog-and-seo.md) і
  [звіту M0](../plans/plan-0010-m0-evidence.md).
- [План дня релізу](fillando-release-day.pdf) — 5 сторінок: шість кроків дня релізу навколо
  `scripts/catalog-release.mjs`, що робити, коли скрипт зупинився, відкат, підготовка й після релізу;
  повна версія — [рунбук](../runbooks/catalog-v2-release.md).
- [Початкова пропозиція](fillando-general-store-proposal.pdf) — концепція з
  прикладами. За актуальними рішеннями дивитися TD-0013 і план, а не статуси
  в історичному proposal PDF.

При зміні плану або звіту виконання перегенерувати поточний PDF у тому самому
пакеті змін. Генератор бере статус із Markdown та дату експорту з локальної дати.
Для кожного завдання підтримувати колонку «Статус» у плані: «Виконано» з
межами перевірки, «У роботі», «Частково виконано» або «Заплановано».
PDF автоматично додає зелені, сині, жовті або сірі позначки з текстом та
підраховує пункти кожного статусу на обкладинці. Не позначати весь пункт
виконаним, якщо готова лише його частина.

```sh
python3 -m venv /tmp/fillando-pdf-venv
/tmp/fillando-pdf-venv/bin/pip install -r scripts/pdf-requirements.txt
/tmp/fillando-pdf-venv/bin/python scripts/export-plan-pdf.py
```

Потрібні шрифти Arial (macOS) або DejaVu Sans (Linux) з кирилицею. Скрипт
визначає корінь репозиторію від свого розташування. Він підтримує структуру
поточних двох документів, а не довільний Markdown. Відносні Markdown-посилання
друкуються як текстові назви; PDF призначений для читання й обміну без репозиторію.

Після експорту перевірити кількість завдань/їх ID, поточний статус, наявність
звіту й відсутність обрізаного тексту. Результат зберігається під незмінною
назвою `fillando-implementation-plan.pdf`, щоб посилання залишалося актуальним.

## План дня релізу

`scripts/export-release-day-pdf.py` збирає `fillando-release-day.pdf` з тексту, узгодженого з
[рунбуком релізу](../runbooks/catalog-v2-release.md): рунбук — джерело правди, PDF — його друкована
форма. Після кожної зміни рунбука (кроки, команди, очікування, stop-критерії, відкат) оновити текст у
скрипті й перегенерувати PDF тим самим venv:

```sh
/tmp/fillando-pdf-venv/bin/python scripts/export-release-day-pdf.py
```

Потрібні Arial і Courier New (macOS) або DejaVu Sans і DejaVu Sans Mono (Linux). Після експорту
переглянути сторінки (`pdftoppm -r 80 -png`): блоки коду не повинні переноситися посеред аргументу.
